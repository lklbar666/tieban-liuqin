# 条文号 → 生肖 固定表

`[复现]` 本表由本仓库作者从两组独立公开例题的 **10 个数据点**复算得出，**10/10 命中、0 反例**。这是本仓库的核心发现，也是"六亲为什么显得准"的算术解释。

## 一、同余式

> **生肖地支序 ≡ 3 + (条文号 − 1151) ÷ 10  (mod 12)**
>
> 地支序：子 = 0、丑 = 1 …… 亥 = 11；适用域为 条文号 ≡ 1151 (mod 10)。

```bash
python scripts/tieban.py zodiac 1251    # → 丑（牛）
python scripts/tieban.py zodiac-table   # → 全表统计
```

实现见 `scripts/tieban.py` 的 `zodiac()` / `numbers_for()` / `table_stats()`，断言见 `scripts/selftest.py`。

## 三、结构后果：周期 120

条文号 → 生肖的周期 = 12 生肖 × 10 编号步长 = **120**。

**推论（可直接推演，不依赖任何命例）：凡两条条文号之差为 120 的倍数，其生肖必然相同。**

例题中的三处印证：

| 配对 | 条文号差 | 差 mod 120 | 结果 |
|---|---|---|---|
| 例1 母（兔）— 子（兔） | 600 | 0 | 必然相同 ✓ |
| 例1 兄弟（牛）— 女（牛） | 600 | 0 | 必然相同 ✓ |
| 例2 兄弟（牛）— 妻（牛） | 360 | 0 | 必然相同 ✓ |

**例 1 中"儿子属兔（与母亲同）""女儿属牛（与兄弟同）"，不是命理巧合，是这张编号表的算术必然。** 在这套编号下，"六亲生肖各不相同"甚至不是默认状态。

## 四、编号之间的差分**不是**固定模板

- 例1：母→兄弟 +100，兄弟→妻 +400，妻→子 +100，子→女 +100
- 例2：母→兄弟 +80，兄弟→妻 +360，妻→长子 +130，长子→次子 +10

**两者不同。** 因此**不能**把六亲编号压缩成"一个参数 + 固定偏移"。

> 这一条曾被我方误推为"固定差分"，在第二个样本上即失效，已撤回。记录在此以作前车之鉴：**单例归纳的规律必须在第二个样本上重验后，才能写进文档。**

## 五、基线概率（含对一处流行误区的更正）

| 量 | 值 |
|---|---|
| 条文库总量 | 12000 条 |
| 每生肖条数 | 12000 ÷ 12 = **1000 条** |
| 不看任何输入、随机取一条六亲条文命中任一生肖 | 1/12 ≈ **8.3%** |

流行的反驳常说「六亲六项全中的概率是 (1/12)⁶ ≈ 3.3×10⁻⁷，所以不可能」——**这个算法是错的**：

1. 六个亲位**不是独立事件**（第三节的 120 周期使它们强相关）；
2. 候选项由编号扫描产生，不是随机抽样。

**把 (1/12)⁶ 当"不可能"来论证该体系是假的，属于无效论证。** 用错论证反驳，会被内行一句话驳回，反而损伤真正有效的论点。

## 六、正确的审计口径

见 `audit.md`。要点：报出**同余表一致项数**、**受 120 周期强制约束的冗余对**、以及**等效独立命中数**（＝网格内条目中出现过的不同生肖个数）。

```bash
python scripts/tieban.py audit --entry "父=1950:蛇,母=1151:兔,兄弟=1251:牛,妻=1651:蛇,子=1751:兔,女=1851:牛"
```

## 七、可核查的限定

- 本表的 10 个数据点取自**网络流传的教材转录（来源等级 D，低）**，该材料含 OCR 错误与招生推广信息。
- 仍予采信的理由：两组例题**互相独立**（不同命例、不同转录者），且 10 个数据点落在**同一条同余式**上且无例外。若转录有随机错误，难以出现这种结构性吻合。
- 适用范围的限定：**限于所引例题**。若日后获得更多命例，应先跑 `zodiac-table` 与本表比对，再决定是否扩大结论。
